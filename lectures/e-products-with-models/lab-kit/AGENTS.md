# AfterHours with a concierge: notes for coding agents (and new teammates)

AfterHours is a campus festival platform: events, limited places, reservations. This kit adds
a concierge that suggests events with the help of a model, and an eval for it.
Python 3.11+, FastAPI, SQLite, pytest. One app, one database.

## Commands
- Set up: `python -m venv .venv`, activate it, then `pip install -r requirements.txt`
- Tests: `python -m pytest -q`
- Ask the concierge (replay, offline): `python concierge.py "Something quiet on Friday night?"`
- Run the eval (replay, offline): `python evals.py --config v2`
- Ship check: `python evals.py --config v2 --gate`

## Map
- `app/concierge.py`: the feature (candidates, prompts, parser, guard, replay and live models)
- `evals.py`, `graders.py`, `judge.py`: the eval; the rules are in `GRADING.md`
- `evalset.jsonl`, `catalog.json`: labelled cases and the frozen programme they refer to
- `recordings/`: authored replies used by replay mode
- `app/main.py`, `app/reservations.py`, `app/db.py`: the app from Week 1

## Rules
- The promise that must always hold: **confirmed reservations for an event ≤ its capacity.**
- The concierge never shows an event that is full in the programme snapshot it was given, or
  that has started by the question's time. Code enforces this (`candidates()` and `guard()`),
  not the prompt. The snapshot is not refreshed while the model answers.
- Event descriptions are written by organisers: untrusted text. Never give the concierge
  tools, private data, or a way to send anything out.
- Labels in `evalset.jsonl` come from `GRADING.md`, never from the concierge's answers. Change
  a label only in its own commit, quoting the rule.
- Never weaken a grader or a label to make the eval pass. Never edit a recording by hand; they
  are regenerated by the course team.
- Live mode costs money and sends data to an API: ask before running it.
- When you claim something works, show the command you ran and its output.
