A 14-week course in software engineering with coding agents

Build It. Prove It. Own It.

Coding agents make code cheap. They do not make software cheap: the right thing, built correctly, safe to run, and changeable by the next person. This course teaches the engineering that turns cheap code into software people can rely on.

Year 2–3 undergraduates 14 weeks · lecture + lab Python · FastAPI · SQLite

The course rule

Every important claim about the software needs evidence. Every consequential decision needs an accountable human.

Agents remove much of what Fred Brooks called the accidental difficulty of programming: syntax, boilerplate, API lookup, glue code. The essential work stays the engineer's responsibility, even when an agent helps with it: deciding what to build, the concepts and rules, the trade-offs, the argument that it is correct, and running it for real people. So the course teaches classic software engineering as the control system for agents. Specifications steer them, architecture contains them, tests and review judge them, permissions limit what they can break, and a person owns the result.

→ Practice

What you build and prove in the lab. Close the race and prove it with a concurrent test.

Some things recur every week: a real case (a failure or a success, fact-checked against its primary source), short agent-off drills done on paper, and a few honest experiments that measure how work actually goes rather than how it feels.

The running project: AfterHours

Teams of four build a platform for a student-run campus festival: browse events, reserve limited places, join waitlists, check people in at the door. Each team picks a festival identity (games, music, film, or maker workshops) and interviews real users. The domain is simple to explain and hides almost every hard problem in the field.

How you are graded

  • Agents are allowed and expected. Disclose meaningful help. You own every line and every claim you submit.
  • We never grade lines of code, prompt length, how much you used an agent, commit counts, or chat logs.
  • Everyone gets the same baseline agent access with spending limits, and saved outputs for when tools are down.
  • Hidden checks only test requirements that were published. Practice defences come before graded ones, with a reassessment path.
